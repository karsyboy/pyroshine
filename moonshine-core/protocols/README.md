# Desktop protocol definitions

The KDE XML files are pinned from `KDE/plasma-wayland-protocols` at
`1db07441870d54157e937674b99380a7dcc0fb32` and retain their upstream licenses.
Rust client bindings are generated by `wayland-scanner` during compilation.

Managed Desktop Mode requires screencast version 4 or newer and
output-management version 18 or newer for custom virtual modes and complete
priority/topology control. Output discovery prefers the registry (version 21 or
newer); otherwise classic per-output globals need device version 18 or newer.
Bindings cap each interface at the pinned XML version. Older incomplete
capabilities are refused before mutation. Compatibility of a specific Plasma
version still requires the documented hardware acceptance matrix.
No KDE implementation code is imported.

`gamescope-input-method.xml` is copied from `ValveSoftware/gamescope` at
`d175688ad4ec490dc7b0695c5c62f8807684a1f1` and retains its license. The isolated
compositor generates server bindings from it for Steam's on-screen keyboard
(see [the compositor guide](../../docs/COMPOSITOR.md#steam-classification-and-input)).

The GNOME adapter uses the private Mutter ScreenCast and DisplayConfig D-Bus
interfaces. It probes native virtual-monitor and configuration capabilities
and verifies applied modes; API presence alone does not establish hardware
compatibility. See [Desktop Mode](../../docs/DESKTOP_MODE.md) for the acceptance procedure.
